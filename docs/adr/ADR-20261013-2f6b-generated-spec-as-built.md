# ADR-20261013-2f6b: `seamspec spec` as built: only approved rules, same bytes from the same ledger

## Context

ADR-20261011-0995 decided that SeamSpec gets a spec generated from the ledger: grouped by area, each locked rule in plain language, retired rules, dead ends, printed by default, `--out` and `--check` for teams that commit a copy. Building it raised questions that plan didn't answer. They are decided here; everything else follows the plan.

## Decision

1. **Proposed rules are not counted inside the document.** The plan said "PROPOSED rules (a count only)". A count in the document changes every time the agent proposes something, so a committed copy would fail `--check` on each proposal, before a human has decided anything. The count is printed **beside** the document instead (*"Not in the spec: 2 proposed rules waiting for review"*; with `--out`, after the "Wrote …" line). The document itself holds only what a human approved.
2. **Same ledger, same bytes.** `--check` only works if the document is a pure function of what is committed: the records and the rule tests they point to. So it has no time of the run, nothing from the local journal (which is why a retired rule shows its reason but no retirement date: that date lives only in the journal), no folder or machine names, and no other look at the disk.
3. **The approver's name, not the email address.** The ledger keeps `Name <email>`. A generated spec is the thing a team is most likely to publish or paste, so it shows the name only.
4. **A rule whose test is missing or changed gets a "Problem" line.** The opening sentence says every rule has a test that must keep passing. `verify` and `doctor` already fail on a tampered test; the document must not go on claiming it.
5. **`--out` overwrites only its own files.** A written copy starts with a "Generated by `seamspec spec`" comment. If the target exists and doesn't start with it, SeamSpec refuses (someone typing `--out README.md` loses nothing). A path inside `.seamspec/` is refused too: that folder is the source.
6. **`--check` never writes**, treats a missing file as out of date, and ignores the difference between Windows and Unix line endings.
7. **Markdown, one layout.** Sections *Rules in force* (by area, then oldest approval first), *Retired rules*, *Tried and failed*. No options for format or filtering in v0.1.
8. **Anyone can run it**, the agent included: it reads the ledger and, with `--out`, writes one file outside `.seamspec/`. It runs no tests and needs neither consent nor a trusted clone.
9. **The area rule moves to `core/area.py`**, shared with the session-start summary, as ADR-20261011-0995 foresaw. **The spec takes the area from the scope text alone.** The summary also asks the disk whether a scope written without a glob or trailing slash is a folder; in the spec that would let an ignored or untracked folder (a local `runs/`, say) change the grouping from one machine to the next and make `--check` fail in CI (Copilot's review of #58). The two can therefore differ for such a scope: the summary says `runs`, the spec says the folder above it.
10. **With no rule in force** the document says *"No rules have been approved yet."*, or *"No rules are in force at the moment."* when rules were approved and later retired. Dead ends alone don't count as approvals: an agent records those without a human.

**Alternatives considered:**
- **Keep the proposed count in the document and have `--check` ignore that line.** Then the printed document and the checked one differ, and "what a human approved" is no longer the whole content.
- **Add a "generated on" date.** It would make every copy stale the next day.
- **Read retirement dates from the journal.** The journal is local to each clone and absent in CI.
- **A `--json` form.** The ledger is already JSON; the point of this command is the readable document.

## Enforced Invariants

Approved by the owner in `seamspec review`, 2026-10-13, as planned in ADR-20261011-0995:
* `inv_f063b724`: the generated spec lists only human-approved rules;
* `inv_4234c6b3`: the generated spec depends on the ledger alone.

## Consequences

- SPEC §15.2 now describes what is built, and the `seamspec spec` row in §15 is no longer marked as planned.
- A team that wants a committed spec runs `seamspec spec --out docs/RULES.md` once and adds `seamspec spec --check docs/RULES.md` to CI. Nothing does this for them: `init` writes no spec file (ADR-20261007-ac04).
- Rule titles and texts are the agent's words, approved by a human; the document prints them as they are.
- The README and the demo can now show the document (week 5).
