# ADR-20261006-9623: seamspec doctor in v0.1 - what it checks, the CI base branch, and what waits

## Context
Week 4 (issue #4) needs `seamspec doctor` and the CI checks in §16.5: CI "blocks a regression and lists retirements on a test PR". SPEC §15 lists more checks than v0.1 can meaningfully run: host tiers, hook installation per host, the MCP token budget, and drift in command templates. Some of those only make sense once v0.2 hosts exist.

## Decision
1. **Checks in v0.1.**
   - **Always:** config, record schemas (each problem names the file), integrity of LOCKED tests, runner-config fingerprints, approval provenance, and a warning for scopes that match no tracked file.
   - **Locally:** the approval journal; `CLAUDE.md` block drift; the git pre-commit hook in enforced and strict mode; and `.claude/settings*.json` allowing `Bash(seamspec…)`, which §12.4.3 rule 6 says `doctor` reports.
   - **In CI (`--ci`):** forward-only and harness protection against the base branch, plus the retirement summary. The local-state checks are skipped, since CI has no journal or hooks.
2. **Forward-only means "only via supersede".** A rule LOCKED on the base branch may become SUPERSEDED. It may not be:
   - deleted;
   - moved back;
   - edited in `title`, `assertion`, `scope`, `verification`, `approved_at` or `approved_by`;

   and its test file must be byte-identical to the base's. This catches an agent that rewrites a test **and** its recorded hash. The local integrity check can't see that, because the hashes agree with each other.
3. **Base branch:** `--base <ref>`, defaulting to `origin/$GITHUB_BASE_REF` on pull requests and `HEAD~1` on pushes. An unreadable base is an error that says `fetch-depth: 0`, so a shallow checkout can't silently skip the check.
4. **The retirement summary never fails.** It lists every status change (including new dead ends, as `(none) → ACTIVE`) and every runner-config fingerprint change, printed and appended to `$GITHUB_STEP_SUMMARY`.
5. **Warnings never fail; errors exit 1.** `--json` gives the full report.
6. **Deferred:**
   - host tiers and per-host hook checks wait for the v0.2 hosts;
   - the MCP token budget stays a test in SeamSpec's own suite, since it's a property of SeamSpec, not of a user's repo;
   - command-template override drift waits for `.seamspec/commands/` (v0.2);
   - checking that each invariant's scope overlaps its runner's `paths` (SPEC §12A) is replaced for now by the more useful "scope matches no tracked file" warning.
7. **Dogfooding:** this repo's CI runs `seamspec doctor --ci` with `fetch-depth: 0` before `verify --all --ci`.

**Alternatives considered:**
- *Forward-only by status only:* rejected. An edited LOCKED test with a re-recorded hash would pass.
- *Base = merge-base with `main` always:* rejected for v0.1. `GITHUB_BASE_REF` is what a PR reviewer compares against, and `--base` covers anything else.

## Enforced Invariants
None yet. Dogfooding candidate: "doctor --ci fails when a LOCKED rule is edited with a re-recorded hash".

## Consequences
* Week 4's CI exit criterion is half done: CI now checks the ledger. Blocking a regression already worked through `verify --all --ci`. The workflow template that `init` installs into user projects is the next PR.
* SPEC §15, §16.5 and §19.11a are updated in the same PR.
